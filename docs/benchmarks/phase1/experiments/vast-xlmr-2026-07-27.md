# Vast XLM-R Five-Type NER, 2026-07-27

## Decision

Promote:

```text
phase1-five-type-xlmr-qa-edu-e12-lr5e5-2026-07-27
```

The selected run reached exact-span F1 `0.723872` on the development chunks. The three-epoch
baseline collapsed to the `O` class, and the `3e-5` learning-rate control was worse than the
selected `5e-5` run.

This is a five-type token-classification experiment, not a generative LLM run. It therefore has no
prompt or decoding parameters. The Qwen branch was deliberately not run because its immutable
model revision, prompt text/hash, and decoding parameters have not been recovered.

## Runtime

The run used the maintained Vast.ai PyTorch template:

```text
image: vastai/pytorch:cuda-12.6.3-auto
template hash: 23077de9080ceec5b9202e517aa8c013
GPU: NVIDIA GeForce RTX 4090, 24 GiB
compute capability: 8.9
CUDA: 12.6
PyTorch: 2.12.0+cu126
Transformers: 5.13.0
precision: BF16
```

The template's Python 3.12/CUDA 12.6 environment was retained because resolving the entire lock on
that host selected an incompatible CUDA build. Top-level ML package versions were installed to
match the run contract where possible, while the template PyTorch build remained `2.12.0+cu126`.
Consequently, the lock hash identifies the intended environment but this run is not a byte-exact
`uv sync --frozen` realization. The complete observed package set is stored in
`environment-freeze.txt` beside each returned run. Reproduction must use both the image tag/template
hash and that freeze file.

One real forward/backward batch was executed before the full runs. It exposed and led to the
Transformers 5 `TrainingArguments` compatibility fix in commit `c499713`.
